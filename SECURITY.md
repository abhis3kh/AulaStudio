# Security reports

Please do not post credentials, personal macros, profiles, recovery checkpoints or diagnostic dumps in a public issue.

For a suspected security vulnerability, use GitHub's private **Report a vulnerability** option if the repository owner has enabled it. Otherwise contact the owner privately through a channel listed on their GitHub profile before sharing sensitive details. Private reporting must be enabled by the owner after publication.

Include the affected version, Windows version, keyboard USB identifiers, minimal reproduction, impact and any proposed correction. Use synthetic keymaps and macros.

Only the current `0.1.x` development line is maintained. There is no guaranteed response time. Releases are unsigned; use the published checksums and source. Known driver-blocking and hardware-recovery limitations are documented in `docs/RELIABILITY.md`.
